# features/anim/

The keycap animations and the guided modes that take over the keycaps for a time: the
Eden startup animation and idle screensaver, the first-run tutorial, the showroom demo,
and the host-driven key attention and host tutorial. `keys_com/poly_keymap.c` starts
them, calls their `*_tick()` functions from housekeeping, asks them which keys to hide
and lets `startup_anim_active()` / `tutorial_exclusive()` stop `update_displays()`.
`lib/hid/hid_com.c` sends HID cmd 31 (replay), 47 and 49 here, and
`lib/split_link/split_sync.c` carries their sync bytes.

## Files

- `startup_anim.c` / `startup_anim.h`: the procedural Eden animation. `startup_anim_start()`
  plays the one-shot intro (`KC_EDEN`, cmd 31), `startup_anim_start_loop()` runs the looping
  idle screensaver (`IDLE_STYLE_EDEN`). `startup_anim_core1_job()` renders one idle keycap
  on core1. It also exports the board geometry (`startup_anim_key_geom()`, `sa_geom_t`)
  and `POLY_INTRO_CONTRAST` for the other renderers here.
- `startup_anim_geom.h`: per-keycap board positions and rotations (`SA_GEOM_LEFT/RIGHT`),
  the splash letters and the sine table `SA_SIN`. Generated by
  `PolyKybdHost/tools/startup_anim_demo.py --emit-geom <out.h> --kle
  polyhost/res/polykybd-split72.json` (in the host repo). Do not edit it by hand.
- `tutorial.c` / `tutorial.h`: the first-run tutorial that follows the Eden intro. The
  master runs the step machine. It has an EXCLUSIVE part (chapter 1, its own sliced
  renderer) and an INTRO part (chapter 2 on, the normal render with hidden keys). The
  pure phase machine is `base/tutorial_plan.c`. Sync: `tutorial_sync_fill()` /
  `tutorial_sync_apply()`, `TUTORIAL_SYNC_BYTES` (6) in `poly_sync_t.tut`.
- `tutorial_names_gen.h`: native language names that need a text shaper (Arabic,
  Devanagari, CJK), pre-rendered as 72x40 keycap tiles (`tut_name_strip_t`). Generated
  by `dev/tools/gen_tutorial_names.py --fonts <dir>` with HarfBuzz and FreeType from the
  Noto fonts in `fonts/noto-fonts.yaml`.
- `tutorial_rgb.c` / `tutorial_rgb.h`: the key LEDs during the Eden show and the lesson.
  While either runs, `tutorial_rgb_paint()` owns the RGB matrix and switches RGB on
  without saving it.
- `focus_ring.c` / `focus_ring.h`: the circular ripple that points at a key
  (`poly_focus_start()`) and the board-sized sweep (`poly_focus_start_sweep()`).
  `poly_focus_overlay()` draws the arc over a legend; `poly_focus_tick()` redraws the
  changed keys within `POLY_FOCUS_SLICE_MS` (3 ms) per pass.
- `key_attention.c` / `key_attention.h`: HID cmd 47. The host asks for the focus ripple
  on one key (op 0 START, op 1 CANCEL) or on a path of layer keys (op 2 GUIDE, parsed
  by `base/attn_guide.c`). The request is synced in `poly_sync_t.attn_*`.
- `host_tutorial.c` / `host_tutorial.h`: HID cmd 49, the host's step-by-step tutorials
  (two status lines, a spotlight that darkens keys, a reveal). The parse and the
  watchdog are `base/host_tutorial_plan.c`. Built only with `POLY_HOST_TUTORIAL`.
- `demo_mode.c` / `demo_mode.h`: the showroom demo (`KC_DEMO`, `KC_DEMO_KEYS`). The
  playlist is `base/demo_plan.c`. The master publishes `{flags, segment}` in
  `poly_sync_t.demo` (`DEMO_SYNC_BYTES`); holding Esc ends it.
- `menu_cascade.c` / `menu_cascade.h`: when the language or emoji layer shows new items,
  the three content rows fade in key by key (`menu_cascade_hidden()`,
  `menu_cascade_tick()`, `CASC_MS`).
- `menu_cascade_rows.h`: each keycap's physical row (`CASC_ROW_LEFT/RIGHT`). Generated by
  `dev/tools/gen_cascade_rows.py` from `split72/keyboard.json`. Run it with `--check`
  to find a stale header.
- `lang_sparkle.c` / `lang_sparkle.h`: small stars that twinkle beside the legends while
  the tutorial shows a language layout (`lang_sparkle_tick()`). Not synced.

## Core concepts

- Sliced rendering: the tutorial, the focus ring and the idle Eden loop draw a few
  keycaps per housekeeping pass and continue on the next pass, so key presses are still
  seen. The one-shot Eden intro renders a whole frame per call and swallows keys.
- Split: the master owns each state machine and sends a small state in `poly_sync_t`
  (`tut[6]`, `demo[2]`, `attn_*`). Each half times its own animation from when it
  received that state, because the two MCUs share no clock. The menu cascade and the
  sparkles send nothing.
- Cores: `startup_anim_core1_job()` runs on core1 (`CORE1_CMD_EDEN_KEY`). Everything
  else here runs on core0.
- Variants: `startup_anim.c`, `tutorial.c`, `focus_ring.c`, `menu_cascade.c`,
  `lang_sparkle.c` and `tutorial_rgb.c` are split72 only and compile to stubs on split42,
  because the geometry tables exist only for split72.
- Storage: all state here is RAM only, except the first-run marker
  (`poly_eeconf_t.boot_flags`, `BOOT_INTRO_DONE` = 0x5A) in `lib/system/state.c`.
- Build switches: `POLY_HOST_TUTORIAL` (not in the DOOM monolith, where cmd 49 NACKs),
  `-e POLYKYBD_TUTORIAL_TEST=yes` (plays the first-run experience once per flashed build,
  test builds only).
- Tests: the pure parts run on the host with `make test:polykybd_tutorial_plan`,
  `polykybd_demo_plan`, `polykybd_attn_guide` and `polykybd_host_tutorial_plan`. The
  files in this folder have no unit test.

## Important

- ⚠️ A draw outside `update_displays()` must go through `poly_key_repaint_begin()`. It
  tracks the panel (an untracked write gives black and half-erased keycaps on the next
  render) and clears the static gfx erase flag.
- ⚠️ The focus ring latches one instant per frame (`POLY_FOCUS_FRAME_MS`). Every slice of
  a frame must draw the same radius, or the ring breaks apart.
- ⚠️ `tutorial_caps_hold()` must be applied right after the host LED snapshot is read in
  `sync_and_refresh_displays()`. Anywhere else the next read erases it.
- ⚠️ A host tutorial report is forwarded to the slave only once. The master resends the
  last TEXT and SPOTLIGHT state and an END from housekeeping until the slave acks it.
- ⚠️ Do not include `startup_anim_geom.h` in a second file. That copies about 1 KB of
  tables into flash. Use `startup_anim_key_geom()`.
