# lib/hid/

The host interface of the master half: the raw HID command handler, the font-pack
transfer and the bulk pipe. The host app (PolyKybdHost) and the HIL rig talk to these
files. QMK calls `raw_hid_receive()` on the half with USB. Handlers that change state
on both halves send it to the slave through `lib/split_link/`.

## Files

- `hid_com.c` / `hid_com.h`: `raw_hid_receive()`. A report whose first byte is `'P'`
  (or `id_custom_save`) is dispatched by `data[1]` through the table `s_hid_cmds[]`
  to one `hid_cmd_N()` function per command (6 to 50). IDs not in the table go to
  `hid_cmd_unknown()`, which tries `hid_fw_up_receive()` and then
  `hid_fontpack_receive()`. Other reports go to `legacy_command_kb()` (the VIA-style
  `enum legacy_command_id`). Cmd 6 is GET_ID: the id string `POLY_GET_ID_STR`, then
  the `V`, `G` and `A` blocks. The file also holds `raw_hid_send_before_reset()`,
  `poly_mark_fresh_boot()` and the MacCompose flag.
- `hid_fontpack.c` / `hid_fontpack.h`: commands 0x50 to 0x53 (`CMD_FONTPACK_BEGIN`,
  `_CHUNK`, `_COMMIT`, `_STATUS`). They flash a PlyF font-pack bundle, or the DOOM WAD
  and engine-pack slots, to both halves with the `lib/fw_update/` staging and relay.
  `fontpack_commit_status()` picks the COMMIT reply: `'.'` both halves finalized,
  `'R'` the master refused, `'L'` the master committed and the slave did not ACK.
- `poly_pipe.c` / `poly_pipe.h`: the bulk pipe, a CDC serial interface next to raw
  HID. Frame: `'P' 'B' cmd len_lo len_hi payload crc32`. Commands: `POLY_PIPE_PING`,
  `_SINK`, `_STAT`, `_RESET`, `_ECHO` and `POLY_PIPE_FW_CHUNK`, which hands up to
  `FW_UP_RELAY_CHUNK_MAX` (236) bytes to `fw_up_xfer_block()`. The pipe has its own
  version, `POLY_PIPE_PROTOCOL` (2). `poly_pipe_task()` drops a frame that stopped
  for `POLY_PIPE_FRAME_IDLE_MS`.
- `mac_compose.h`: `mac_compose_set()` / `mac_compose_active()`. MacCompose is cmd 20
  value 6: in macOS unicode mode, F20 is held instead of Option. RAM only; defined in
  `hid_com.c`.

## Core concepts

- Reports are 64 bytes. A reply starts with `'P'`, the command ID and a status byte.
  Since protocol v3 the firmware sends no unsolicited raw HID reports.
- `PROTOCOL_VERSION` (38) and `FW_VERSION` are in [`../../config.h`](../../config.h).
  The host compares `PROTOCOL_VERSION` with its `__protocol__` at connect.
- The host polls GET_ID every second. The `G` block is `poly_state_generation()`;
  firmware calls `poly_state_touch()` to tell the host that board state changed.
- Commands 10, 11, 12, 16 to 19, 21, 33, 41 and 42 have the flag
  `HID_CMD_OVERLAY_BURST`, which coalesces the renders of a program switch.
- Parts of `hid_com.c` are generated by cog from `lang/lang_lut.xlsx` (the language
  lists of cmd 7 and cmd 27). Regenerate with `cog -r lib/hid/hid_com.c` from
  `keyboards/polykybd/`, or with `dev/scripts/run_cog.sh`. Do not edit between
  `[[[cog` and `[[[end]]]` by hand.
- `poly_pipe.c` is built only with `POLYKYBD_BULK_PIPE=yes` (the default, which sets
  `VIRTSER_ENABLE`). Cmd 32 exists only with `POLYKYBD_LOOP_PROFILE`, cmd 49 only with
  `POLY_HOST_TUTORIAL`.
- The COMMIT status contract of `fontpack_commit_status()` is tested by
  `make test:fw_up_verdict`.

## Important

- ⚠️ A new command or a changed reply needs `FW_VERSION`, `PROTOCOL_VERSION` and the
  host's `__protocol__` raised together. Use the `add-gated-hid-command` skill.
- ⚠️ Anything added to the GET_ID reply goes after the `V` font-pack block. The host
  reads the blocks by position. The size is a `_Static_assert` in `hid_com.c`.
- ⚠️ A `*_set_user` hook is a notification, never a setter. Calling one moves the UI
  and not the behaviour.
- ⚠️ State that a host report sets goes to the slave as that report, in
  `dynamic_keymap_sync_t.commands` on `USER_SYNC_DYNAMIC_KEYMAP_DATA` (as cmd 14 and
  the keymap writes do).
- ⚠️ A pipe handler runs inside `virtser_task()` on the main loop. The host must wait
  for the replies to `POLY_PIPE_FW_CHUNK`, or the main loop stays in `virtser_task()`
  for the whole transfer.
