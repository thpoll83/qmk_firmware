# polymod_prc

A decoder for 1-bit images coded with **PRC** (Predictive Range Coding), plus a
Python tool that trains probability tables and encodes images for it.

PRC codes an image pixel by pixel. The 10 already-decoded neighbours of a pixel
select one of 1024 contexts; a fixed table gives P(pixel is 0) for that context;
a binary range coder spends almost nothing on pixels that match the prediction.
The idea is JBIG's (the fax standard); the format is our own and is not
JBIG-compatible. On PolyKybd's 72×40 keycap icons it needs ~26-30 bytes per icon,
against ~87 for the best RLE variant, so nearly every icon fits one 64-byte HID
report.

## Files

| File | What it is |
|---|---|
| `polymod_prc.c/.h` | The decoder: `prc_decode_roi()` for the default frame, `prc_decode_roi_in()` for any frame up to 255×255 |
| `prc_table_v1.h` | PolyKybd's table v1, trained on its overlay templates. Frozen: its bytes are part of PolyKybd's HID protocol v19 |
| `tools/prc_tool.py` | Trains a new table from your images, writes its C header, and encodes images |
| `tests/` | `make test:polymod_prc`: golden vectors generated by PolyKybdHost's encoder, decoded and compared byte for byte |

Pixel layout: row-major, most significant bit first, rows packed back to back with
no padding (bit index `y * frame_w + x`). The decoder clears the whole frame, then
fills the region of interest (ROI); pixels outside it read as 0.

## Using it

List the module in your `keyboard.json`; listing it is the whole enable:

```json
"modules": ["polykybd/polymod_prc"]
```

```c
#include "polymod_prc.h"
#include "prc_table_v1.h"   // or a table you trained

uint8_t frame[32 * 16 / 8];
bool ok = prc_decode_roi_in(frame, 32, 16, top, left, height, width, payload, len, prc_table_v1);
```

The default frame for `prc_decode_roi()` is 72×40; define `PRC_FRAME_W` and
`PRC_FRAME_H` before including the header to change it at build time.

## Training a table for your images

The v1 table was trained on PolyKybd's keycap icons. Images with a different
character (text, dithered photos, thin line art) compress better with a table
trained on them.

```sh
pip install pillow
python3 tools/prc_tool.py train icons/*.png --table-id 2 \
    --header prc_table_v2.h --bin prc_table_v2.bin
# A sprite sheet: split it into 72x40 cells first
python3 tools/prc_tool.py train sheet.png --cell 72x40 --table-id 2 --header prc_table_v2.h
```

A pixel at or above grey level 128 counts as lit (`--threshold`, `--invert`).
Empty images and duplicates are skipped. The result is deterministic: the same
images in any order give the same table.

Encode with it, and check the size:

```sh
python3 tools/prc_tool.py encode icon.png --table prc_table_v2.h
```

`encode` prints each image's ROI box and payload in hex, and decodes every
payload again to check the round trip.

⚠️ **The encoder and the decoder must use the same table.** A decoder given a
different table than the one used to encode draws garbage, and nothing reports an
error. Treat a table that has shipped as frozen, and give a retrained one a new
id rather than overwriting it. The tool refuses to overwrite an existing table
with different bytes unless you pass `--force`.

## Where the format is defined

`tools/prc_tool.py` is a port of PolyKybdHost's `polyhost/util/prc_codec.py`, the
encoder PolyKybd's host uses. Both must stay step-for-step identical to the
decoder here: the template order, the zero padding outside the ROI, the
probability scale and the range coder.
`keyboards/polykybd/tools/tests/prc_tool_test.py` checks that the tool reproduces
the host's golden payloads byte for byte, and its trainer was checked against the
host's on the full set of PolyKybd templates (1007 cells, identical tables).
