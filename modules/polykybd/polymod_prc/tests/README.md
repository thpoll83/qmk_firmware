# polymod_prc/tests/

The unit-test suite `polymod_prc`. It decodes golden vectors that the host's PRC
encoder produced and compares every byte of the result. Nothing on the HIL rig can tell
a wrong pixel from a right one, so this suite is the check that host and firmware use
the same format.

## Files

- `prc_tests.cpp`: 8 googletest cases in `PrcCodec`:
  - `GoldenVectorsDecodeToTheHostsOverlay`: each entry of `prc_vectors` decodes with
    `prc_decode_roi()` and matches all 360 bytes of its overlay. The output buffer is
    filled with `0xA5` first, so the decoder must clear what it does not draw.
  - `TableIsTheFrozenV1`: `PRC_TABLE_ID` is 1, every one of the 1024 entries is at
    least 1, the byte sum is 135654, and entries 0, 511 and 1023 are 252, 177 and 13
    (values from PolyKybdHost `polyhost/res/prc_table_v1.bin`).
  - `BoxOutsideTheFrameIsRefusedAndLeavesTheOverlay`, `BoxOutsideACustomFrameIsRefused`:
    an empty or out-of-frame ROI returns `false` and writes nothing.
  - `FullFrameBoxIsAccepted`, `ReadingPastThePayloadIsSafe` (a truncated payload must not
    read past `len`).
  - `AnyFrameSizeDecodesTheSamePixels`: `prc_decode_roi_in()` with an 80x48 frame puts
    the ROI on the same pixels and writes nothing past the frame.
  - `PayloadLongerThan255BytesDecodes`: the 571-byte `prc_long_payload`.
- `prc_vectors.h`: generated by PolyKybdHost `tools/gen_prc_vectors.py`. Do not edit.
  `prc_vector_t` holds the ROI box, the payload, the expected overlay, and a cmd 41
  record (keycode, modifier, `record`). Eight vectors: two single pixels, a solid
  10x10 block, an 8x8 checkerboard, and template cells 0, 312, 624 and 936.
- `prc_long_vector.h`: generated with `../tools/prc_tool.py`. Do not edit. A 72x40
  frame of random pixels (Python `random.seed(7)`) encoded with table v1, and its
  expected overlay `prc_long_overlay`.
- `testlist.mk`: adds `polymod_prc` to `TEST_LIST`. Included from
  `builddefs/testlist.mk`.
- `rules.mk`: links `polymod_prc.c` and the test, with this folder on the include path.
  Included from `builddefs/build_test.mk`.

## Core concepts

- The decoder is pure C with no globals, so the suite needs no mocks.
- `prc_vectors.h` is also read by two other tests:
  `keyboards/polykybd/base/tests/prc_record_tests.cpp` (suite `polykybd_prc_record`, the
  cmd 41 record header) and `keyboards/polykybd/dev/tools/tests/prc_tool_test.py` (the
  Python encoder must give the same payload bytes).
- Run: `make test:polymod_prc`. CI runs it in `polykybd-unit-test.yml`.

## Important

- ⚠️ A mismatch in `GoldenVectorsDecodeToTheHostsOverlay` means host and firmware no
  longer use the same format. Fix the code, not the vectors.
- ⚠️ To change the vectors, regenerate them in PolyKybdHost with
  `tools/gen_prc_vectors.py`. That script also pins them on the host side.
- ⚠️ Judge a run by the `[  PASSED  ] 8 tests.` line, not by the exit code.
